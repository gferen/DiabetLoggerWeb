# Action Plan — Structured данни за по-добър CGM анализ

> **Статус: ✅ ЗАВЪРШЕН** (16.11.2026)

---

## Какво беше планирано

Разделен timestamp доза/хранене, физическа активност, алкохол, грамаж въглехидрати при хипо, дати на смяна ампула/сензор.

## Какво беше реализирано

### Фаза 0 — Backend ✅
- Нови типове: `activity`, `alcohol`, `device_change` + `meta` JSON поле (по-гъвкаво от отделни колони)
- `meal_time` и `carbs_g` колони за разделен dose/meal timestamp
- `basal_profiles` таблица с CRUD API (`/api/profiles`)
- Pydantic валидация обновена

### Фаза 1 — Web frontend ✅
- Всички нови типове с табове и форми в `index.html`
- Помпа поддръжка: delivery (помпа/писалка), bolus kind (нормален/удължен/комбо), insulin type
- BG source (свой/болничен/CGM)
- Бързи бутони: Ниска, Цигара, Нощен комплект
- Помпа панел: Темп базал, Болус, Спиране, Възобновяване
- Пач информация: напълнено, остатък, място на тялото
- Етикети за периоди (болница/пътуване/болест/стрес/активен ден)
- Темп базал визуализация на графиката (цветни ленти)
- Период визуализация на графиката
- Профили на помпата (`profiles.html`): създаване, редакция, сравнение
- BT глюкомер import от Juggluco `/x/amounts`
- `logger2diabetesm.py` конвертор
- Пълен mobile-first редизайн с Sofia Sans, тъмна тема, PWA

### Фаза 2 — Android ❌ (по план)
Не е пипан — web UI покрива нуждите. Android приложението остава за бъдещо обновяване.

### Фаза 3 — Тестване ✅
- Всичко тествано с реални данни (помпа Medtrum Nano + Libre 2 CGM + Contour Next One BT глюкомер)
- `qa.py` обновен с тестове за profiles CRUD
